1. EXECUTIVE SUMMARY

Pin'Go CRM is a Symfony 6.4 LTS web application currently structured as a
Twig-rendered CRM interface. The project has a standard Symfony backend,
frontend assets managed by Symfony Asset Mapper/importmap, and a PostgreSQL
database configuration prepared through Doctrine.

At the current stage, the application behaves mainly as a UI prototype:
controllers render Twig templates, the page data is mostly hardcoded inside
Twig files, and there are no committed domain entities, repositories,
migrations, forms, or business services yet.

Main application areas:
- Login page
- Rendez-vous dashboard
- Client management page
- Consultation list page
- Consultation detail page
- Reusable sidebar, logo, and icon Twig components

13. CURRENT APPLICATION LIMITATIONS

Architecture limitations:
- No domain model is implemented yet.
- No database tables/migrations are implemented yet.
- No repositories are implemented yet.
- No application services are implemented yet.
- Controllers do not pass dynamic data to Twig.
- Twig templates contain mock data arrays.
- Login is not connected to Symfony authentication.
- Forms post to placeholder "#".
- Search, filters, pagination, export, edit, delete, add, payment, and modal
  actions are UI-only at the moment.
- Stimulus is installed but not used for the current CRM interactions.
- A generated example Stimulus controller remains in assets/controllers.

Environment limitations:
- PATH php is 7.4.33 and cannot run the project.
- PHP 8.3 is available through WAMP but appears to miss the database PDO driver.
- Xdebug tries to log to c:/wamp64/logs/xdebug.log, but that file could not be
  opened during console commands.

14. RECOMMENDED NEXT ARCHITECTURE STEPS

1. Fix local runtime alignment
   - Put PHP 8.3 or another PHP >= 8.1 binary first on PATH.
   - Enable the PostgreSQL PDO driver for that PHP runtime.
   - Ensure Xdebug log path exists or disable Xdebug for normal development.

2. Implement authentication
   - Create User entity.
   - Configure a Doctrine user provider.
   - Add Symfony login authenticator.
   - Add logout route.
   - Protect CRM routes with ROLE_USER or more specific roles.

3. Introduce the domain model
   - Add entities for Client, RendezVous, Consultation, PaymentMethod,
     Payment, Comment, HistoryEvent, Consultant/Voyant, and Forfait as needed.
   - Generate Doctrine migrations.
   - Replace hardcoded Twig arrays with database-backed data.

4. Add application services
   - Keep controllers thin.
   - Move workflow logic into services such as ClientService,
     RendezVousService, ConsultationService, PaymentService, and HistoryService.

5. Add forms and validation
   - Use Symfony Forms for login/auth flows, client search, client edit/add,
     consultation edit/add, comments, and payment methods.
   - Add validation constraints to entities or DTOs.

6. Move page interaction logic into Stimulus
   - Sidebar controller
   - Panel toggle controller
   - Modal controller
   - Table/search/filter controller if needed

7. Add tests
   - Controller smoke tests for public routes.
   - Security tests for protected routes after authentication is implemented.
   - Entity/repository tests for core persistence behavior.
   - Service tests for CRM workflows.
